# jamesshin.tech

[![CI](https://github.com/jamesshintech/jamesshin.tech/actions/workflows/ci.yml/badge.svg)](https://github.com/jamesshintech/jamesshin.tech/actions/workflows/ci.yml)

The source of [jamesshin.tech](https://jamesshin.tech): my name, one line of background, two work samples (a billing-controls essay and a finance-platform proposal), and four products I built and shipped, each shown by a recording of the real app. The home page is set in the room from Yonmoku, my 3D board game, rebuilt in three.js; every item is a row in the column and an object in the room. Essays are under `/writing`.

Every route, including the OG image, is prerendered at build time. There are no cookies, analytics or client-side tracking. First-load JavaScript stays close to Next.js's own baseline (102 kB shared; 111 kB for the home page); three.js and the room load after the page is idle, from their own chunk (134 kB gzipped) and 228 kB of textures. No text is animated, and the column is complete with JavaScript off, without WebGL and under reduced motion.

## How it works

- **Next.js 15 App Router, fully static.** `/`, `/writing`, each essay, the RSS feed, the sitemap and the OG image are all built ahead of time.
- **Essays are Markdown in [`content/essays/`](content/essays).** [`lib/writing.ts`](lib/writing.ts) parses frontmatter with gray-matter and renders with remark and remark-gfm. Two small remark plugins: one wraps every table in a keyboard-focusable region that scrolls sideways, so a wide table never scrolls the page; one sets typographer's quotes in prose while leaving code, raw HTML and link targets untouched.
- **Diagrams are HTML, not images.** Each figure is an ordered list styled by the design system. It reflows at 320px, screen readers read it as a list, and RSS readers that drop CSS still get the content. Figures are left out of the reading-time word count.
- **Products are shown by recordings, never static screenshots.** [`VideoLoop`](components/story/VideoLoop.tsx) plays a WebM/MP4 loop in the product's panel, with a poster frame taken from the same recording. Under reduced motion it holds the poster and offers a Play button, which sits outside the recording's link so it is reachable by keyboard and screen reader.
- **The home page is a room.** [`StudyHome`](components/home/StudyHome.tsx) server-renders the column, where every row is a real link, then imports the room once the page is idle. [`lib/room/scene.ts`](lib/room/scene.ts) builds Yonmoku's room from the game's own spec and textures; [`stage.ts`](lib/room/stage.ts) is the runtime; [`runner.ts`](lib/room/runner.ts) seats the camera at the table and frames the view beside the column (`setViewOffset`; on phones, a field of view computed for the strip above the column). Choosing a row turns the view to its object and lights it; a product's row or object opens a panel with its recording. Everything the room adds to the page (canvas, listeners, observers, a timer, GPU memory) is released when the visitor navigates away, the GPU context is lost, or startup fails.
- **Every state machine is written down.** The room's lifecycle (waiting, loading, live, or a picture with its reason) and what the reader is looking at (pointer hover, keyboard focus, and a closed, pending or open panel) are reducers in [`lib/room/state.ts`](lib/room/state.ts), unit-tested; the frame loop is one life plus a set of reasons it is held; pointer gestures, resolution and the falling bead each have their states named at the top of their code. Bugs that lived between flags (a late pick opening over a later choice, hover stealing focus's highlight, a right-drag turning the view, reduced motion read once) each have a test.
- **Phones.** Every drag on the room turns the view; the page scrolls from the column. Up to 2x resolution with antialiasing, and pictures rendered at 3x. A chosen item opens full screen, the recording the large part.
- **The techniques are in the shaders, not in extra draw calls.** Bamboo shadows on the shoji paper are computed in its fragment shader from sixteen leaves and four stems moved on the CPU (kage-e); the bath runs the height-field wave equation on a 128² half-float ping-pong target, stepped at 60 Hz on the GPU after Evan Wallace's WebGL Water, so the spout's drips and the visitor's pointer ripple it; the water reflects a PMREM of the garden's own sky with the sun or moon in it, rebuilt only when the light has moved; a fresnel rim (`onBeforeCompile` with its own program cache key) lights the active object; the bamboo sways in its vertex shader. The light blends continuously from the visitor's clock. 92 draw calls in the main pass, 32.5k triangles.
- **It is built not to strain a laptop or a phone.** Device tiers, pixel-ratio caps (1.8, or 1.4 on the low tier), pausing in hidden tabs, and still frames under reduced motion follow [MengTo/threeui](https://github.com/MengTo/threeui). Beyond that: 30 frames a second at rest, the high tier's 60 only for a moment after the visitor does something ([`frameBudget`](lib/room/stage.ts)); the loop stops when the part of the page the room shows through scrolls away or a phone's panel covers it (the canvas itself is fixed and never "off screen"); the shadow map is drawn only when the light changes or a bead falls; the pixel ratio steps down when frames run over budget; a browser that draws WebGL on the CPU gets the picture, never the room ([`webglSupport`](lib/room/support.ts)); the build yields to the main thread between stages and shaders compile in parallel where the browser supports it. At rest on a desktop it uses about 3% of the main thread; on a phone with the room covered, none. `?debug=1` shows a frame meter. Without WebGL 2, with Save-Data on, or after a lost context, the room stays a still of the same render (`public/room/poster-*.webp`, picked by time of day before first paint; regenerate with `node scripts/room-posters.mjs`).
- **Motion can be paused.** One switch ([`lib/motion.ts`](lib/motion.ts), [`MotionToggle`](components/home/MotionToggle.tsx)) stops everything that moves on its own, the room and the recordings, as WCAG 2.2.2 asks; the choice is remembered and restored before first paint.
- **No decoration on the interface.** No animated text, no scroll-progress bar, no pointer effects outside the room: the room and the recordings carry the page.
- **One design system, written down.** [`DESIGN.md`](DESIGN.md) defines the colors, type, spacing, every component and the decisions that led here, including what was tried and cut.

## What the tests guard

Playwright tests, run with no retries so a flaky test fails instead of passing on its second try. Those in [`e2e/site.spec.ts`](e2e/site.spec.ts) drive a browser; in CI they run against the production build (`next start`). Those in [`e2e/writing.unit.spec.ts`](e2e/writing.unit.spec.ts) test the essay pipeline directly. They cover:

- **Layout at real widths.** On desktop the column is fixed beside the room; on phones it starts 46% down, over the room, and a product's panel is a sheet from the bottom. Every row and link is at least 44px tall and every hotspot 48px. Reading pages keep one left edge, and a short one keeps its footer at the bottom of the window. No sideways scroll at 320, 390, 768, 1024 or 1440px. The nav stays on one row and the name never wraps, from 320 to 1440px.
- **Essay rendering.** Figures and tables fit at 320, 390, 520, 820 and 1440px. That check forbids mid-word breaks, so a word that does not fit shows up as overflow instead of being silently split.
- **Content contracts.** The billing essay keeps its publication date and revision date, bottom line, both diagrams, three tables and four footnotes, and the Stripe quote matches its source character for character. Claims a billing or audit reader would check stay corrected (SOX prescribes no control types; self-release under the limit is called a compensating control). The essay taken off the site redirects to `/writing`; the RSS feed and sitemap no longer list it.
- **The room.** None of three.js is in any script the home page's HTML names. The room loads without a console error, inside its budgets (110 draw calls, 40k triangles, 40 shader programs). Its light and the picture shown while it loads agree on either side of both hand-offs (17:30, 19:30). A row lights its object and pins its label; a product's row or object opens its panel with the recording playing and focus on Close, and Escape or Close returns focus to the row; the board drops a bead first. Navigating away releases the room and coming back rebuilds it. Without WebGL 2, with WebGL drawn by the CPU, or with Save-Data on, the picture stays and the panels still work. At rest it draws at most 30 frames a second; on a phone it stops while the column or a panel covers it; a resting frame skips the shadow pass. Without JavaScript every row is a link. The column's own tests run with Save-Data on, so on a CI runner, where WebGL is software, they never wait on the room.
- **Behaviour, not just content.** No animation is running when the page loads, and no progress line or reveal is on the page. The proposal PDF is served as a real PDF, its label carries its real size, its provenance note names neither company nor role, and neither does the file's own title. Reading pages share with the site's preview image. Every response carries `nosniff`, a referrer policy and no-framing headers. The word count leaves figures, code and footnote markers out. Missing frontmatter fails loudly, naming the file. Tables get their scroll region and show a soft edge where there is more. JSON-LD cannot close its script tag early.
- **Accessibility.** A pause switch stops the room, is remembered across reloads and client-side visits, and is offered even when the room is a picture; under reduced motion the room draws still frames, the switch is hidden, and a recording's Play control becomes Pause and keeps focus; every page starts with a skip link to its one `main`.
- **Privacy.** Published pages must not contain personal contact details or leftovers from the site's previous version. The personal patterns live in a CI secret rather than the repo, and a failure reports which pattern matched by number, not by text. Retired routes return 404, and the RSS feed and sitemap use only the current domain.

Checks that guard against a past bug were run against that bug first and seen to fail; the reduced-motion test found one on its first run (the Play button sat inside a link hidden from assistive tech). The room's guards were each checked the same way, by breaking what they guard (three.js imported statically, the picture's time rule moved half an hour, no release on navigation, focus not returned, reduced motion ignored, no bead) and seeing the matching test fail. Locally and in CI, headless Chromium gets WebGL 2 from SwiftShader (`--enable-unsafe-swiftshader`).

## Build

```bash
pnpm install
pnpm dev        # http://localhost:3000
pnpm build && pnpm start
pnpm lint && pnpm typecheck
pnpm test:e2e
```

Node 22 (CI and Vercel use the same major). Fonts are the `@fontsource` packages' latin files, loaded with `next/font/local`, so the build fetches nothing from Google (Google Fonts began answering Vercel's builders with CSS `next/font/google` could not parse on 2026-11-02).
